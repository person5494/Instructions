# SkillSwap — предложение по декомпозиции логики приложения

## Назначение документа

Документ фиксирует предложение по декомпозиции задач по логике SkillSwap после завершения основной статической desktop-вёрстки.

Основа декомпозиции:

- актуальная модель данных и логики SkillSwap;
- фактически согласованные пользовательские сценарии;
- существующая Redux Toolkit-инфраструктура проекта;
- уже созданные UI-компоненты, widgets и pages из этапа вёрстки.

Принцип работы:

1. Сначала привести в порядок модель данных и статические справочники.
2. Затем подготовить browser storage и Redux-state.
3. Затем реализовать независимые доменные сценарии: регистрация, авторизация, Favorites, заявки, уведомления.
4. После этого подключить логику к каталогу, странице навыка и профилю.
5. В конце — тесты, интеграционная проверка и удаление устаревшей логики.

Важно:

- существующие UI-компоненты повторно не создаются;
- если компонент уже свёрстан, задача по логике должна подключать к нему данные, state и handlers;
- отдельная доменная сущность `Skill` с собственным `id` не используется;
- один браузер поддерживает максимум одного локально зарегистрированного пользователя;
- настоящий backend не реализуется;
- задачи должны оставаться достаточно небольшими для отдельных PR.

## LOGIC-44 — Интеграционные тесты основных пользовательских сценариев
